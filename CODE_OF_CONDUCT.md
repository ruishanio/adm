# Code of conduct

English | [简体中文](#行为准则)

ADM welcomes people with different backgrounds and levels of experience. This code applies to the repository's issues, pull requests, reviews, and other project spaces, including when someone represents ADM publicly.

## Working together

- Be respectful. Discuss ideas and code without attacking the person behind them.
- Give constructive feedback, explain your reasoning, and allow room for mistakes and different perspectives.
- Do not harass, threaten, discriminate, use sexualized language or imagery, or repeatedly disrupt discussions.
- Do not publish another person's private information without permission, including device identifiers, logs, and screenshots containing personal data.
- Do not retaliate against someone who reports a concern in good faith.

## Reporting and enforcement

Use the offending issue, pull request, or comment's **Report content → Report to repository admins** action to report a concern privately. Include a link to the content and brief context. Do not open a public issue containing private details or accusations.

If that option is unavailable, or the concern involves a repository administrator, use [GitHub's abuse reporting channels](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam). GitHub handles those reports under its own policies. For software vulnerabilities, use [the security policy](SECURITY.md) instead.

Maintainers review reports in context, limit disclosure of identifying details to what is needed to handle the report, and may request a correction, remove content, restrict a discussion, or temporarily or permanently restrict participation. The response should reflect the severity, impact, and recurrence of the behavior. Maintainers are subject to the same standards.

## 行为准则

ADM 欢迎不同背景和经验水平的参与者。本准则适用于仓库的 Issue、PR、代码审查及其他项目交流空间，也适用于公开代表 ADM 的行为。

### 共同协作

- 尊重他人，对事不对人，就观点和代码展开讨论。
- 提出有建设性的反馈，说明理由，允许犯错并尊重不同意见。
- 不得骚扰、威胁、歧视、发表带有性意味的言论或图片，或反复扰乱讨论。
- 未经同意，不得公开他人的私人信息，包括含有个人数据的设备标识、日志及截图。
- 不得报复善意反馈问题的人。

### 反馈与处理

在相关 Issue、PR 或评论的菜单中，选择 **Report content → Report to repository admins**，私下向仓库管理员反馈，并提供内容链接及简要背景。不要通过公开 Issue 发布私人细节或指控。

如果没有此入口，或问题涉及仓库管理员，请使用 [GitHub 的滥用举报渠道](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam)，由 GitHub 按其政策处理。软件安全漏洞请改用[安全政策](SECURITY.md#安全政策)中的渠道。

维护者会结合上下文评估，限制身份信息在处理所需范围内披露，并根据行为的严重程度、影响及是否反复发生，采取要求纠正、移除内容、限制讨论或暂时／永久限制参与等措施。维护者同样遵守本准则。
