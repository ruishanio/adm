# ADM 多语言方案

## 本轮实现

- 在“设置 → 通用”选择“简体中文 / English”，立即生效，无需重启；不提供持续跟随系统的选项。
- `src/shared/i18n.ts` 集中管理界面文案、具名参数和支持的语言；中文文案为键，英文词典通过 TypeScript 约束键名。组件和状态层调用 `t()`，不按语言复制组件。
- `language` 保存在原有用户配置中，Rust 仅接受 `zh-CN`、`en`。手动选择时写入成功后切换界面；保存失败维持原语言。旧配置缺省、旧版 `system` 或未知语言只重置语言项，不丢失设备备注等偏好。
- 首次启动读取系统首选语言：简体中文地区及 Hans 使用简体中文；其他无对应翻译的语言（含繁体中文）使用英语，不扫描系统次选语言。结果立即保存，之后系统语言变化和设备轮询均不重新决定语言。首次保存失败时显示错误，本次仍使用识别结果，后续启动再尝试保存。
- 菜单项、标签、按钮、提示、表单与辅助功能标签使用同一词典。文件修改时间按当前语言格式化；设备名、路径、包名、组件名称和协议值不翻译。
- 名称始终使用 ADM；Device manager for Android 仅用于关于说明。
- macOS 原生菜单在启动时读取同一语言偏好，切换语言时同步重建“文件、编辑、显示、窗口、帮助”及其应用菜单项，保留系统动作和快捷键；配置保存失败时恢复原菜单。翻译集中在 `src-tauri/src/native_menu.rs`。Windows 保持现有无原生菜单栏布局。

## 后端与系统边界

当前切换覆盖应用前端界面、前端任务提示及 ADM 创建的 macOS 菜单项。Rust 校验错误、设备所有者条件检查说明、原生文件选择器的自定义标题，以及 ADB / Android 返回的诊断仍保留原文；Apple 菜单、系统注入的服务内容和系统选择器的系统按钮遵循操作系统。本轮不将中文错误字符串解析为业务状态，也不通过替换字符串修改 ADB 原始输出。

后续完整本地化时，将 Rust 自有业务错误改为结构化 `{ code, params, detail }`，前端按稳定错误码翻译面向用户的说明，同时保留 `detail` 便于诊断。原生对话框通过解析后的语言设置标题；不能依赖中文文案判断安装、连接或所有者操作是否成功。

## 增加语言

1. 将中文键提取为共享 MessageKey，新增完整的 `Record<MessageKey, string>` 词典并注册语言代码。
2. 扩充语言选择项、系统匹配、Rust 白名单及原生菜单翻译；保持缺省兼容。
3. 具名参数必须与源文案一致，不用字符串拼接处理路径、数量和设备名。语言自称（例如 English、简体中文）固定展示。
4. 运行字典参数一致性、即时切换、保存失败回退和偏好重载测试；实测最小窗口、长文案、连接弹窗固定高度与表格滚动。

当前仅支持从左到右布局；新增阿拉伯语等语言前需要专门验证 RTL、图标方向和路径编辑。需要复杂复数、性别或 ICU 语法时，再以保持现有调用边界为前提接入成熟的格式化库。
