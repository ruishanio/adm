# ADM 代码整理方案与实施记录

日期：2026-11-02。基线：`65cabec`（v0.1.2）。已完成本轮整理，技术栈仍为 Tauri 2 / Vue 3 / TypeScript / Rust，版本保持 0.1.2。2026-11-03 按用户授权提交并推送本轮改动，不创建 tag；具体提交以 Git 历史为准。

## 整理结果

本轮围绕职责划分、异步边界、资源回收和维护检查整理代码，保留已确认的界面及 IPC 协议，没有引入新状态库或升级依赖。

| 范围       | 原来的问题                                                     | 已实施                                                                                                         |
| ---------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 工作台状态 | `workbench.ts` 543 行，设备、应用、安装、目录与 Owner 逻辑交织 | 领域状态迁入 `features/`，入口减至 150 行，负责组合、公共调度、快捷键和生命周期                                |
| 页面       | 详情确认、文件任务和页面布局混在一起                           | 提取 `AppDetailsDialog.vue` 与 `files/actions.ts`；应用、文件、日志、性能组件各归所属功能                      |
| Rust 入口  | `lib.rs` 580 行，状态、协议解码、业务路由与应用生命周期集中    | 入口减至 109 行；服务状态归 `service.rs`，请求按六个领域放入 `commands/`                                       |
| 进程回收   | Logcat 停止只发取消信号，退出没有集中确认客户端结束            | 统一登记本实例启动的客户端，退出阻止新进程并回收已有客户端；日志持有线程句柄并有限等待                         |
| 样式       | `styles.css` 2,768 行，页面与平台覆盖难定位                    | 主入口 18 行，固定顺序导入 14 个样式模块；生产 CSS 内容摘要保持一致                                            |
| 应用选项   | 日志与性能选择器各自读取、排序和映射                           | 共用 `lib/app-options.ts`，合并并发读取，使用 5 秒短缓存；手动刷新强制读取，设备、应用状态和界面语言变化时失效 |
| 格式化     | 二进制计算配合 KB/MB 标注，不同页面缺失值处理不同              | 共用 `lib/format.ts`，统一 KiB/MiB/GiB；缺失或非法值显示 `—`，零值仍显示零，保留各场景精度                     |
| 无用文件   | 生成组件附带未用包装，未用变量缺少约束                         | 删除 15 个无引用包装组件及导出；开启未用变量、参数检查；新增源码引用检查并接入构建                             |
| 文档与产物 | 历史验证混入当前规范，旧 Electron 产物留在工作区               | 历史记录归档，开发文档同步当前结构；约 1.10 GB 旧产物可恢复地移入废纸篓                                        |

行数用于定位职责，不作为拆分目标。例如 `apps.rs` 的大量代码是同模块测试，本轮没有为了缩短文件把有关联的业务校验打散。

## 当前目录与边界

```text
src/renderer/
  features/
    devices/                  设备快照、选择与信息
    apps/                     应用列表、资源、详情与确认
    install/                  APK 选择、解析与安装弹窗
    files/                    目录状态、列表与文件操作
    logs/                     Logcat 会话、筛选与列宽
    performance/              性能会话、页面与图表
    owner/                    所有者预检与确认
  composables/workbench.ts    领域组合、公共调度与生命周期
  components/                跨功能控件和基础 UI
  lib/                       IPC、格式化、应用选项及公共类型
  styles.css                 样式导入入口
  styles/                    语义变量、共享控件和各功能样式
src-tauri/src/
  lib.rs                     原生应用装配及窗口、退出事件
  service.rs                 共享状态、串行操作和取消
  child_process.rs           本实例客户端登记与回收
  commands/                  设备、应用、文件、日志、性能、设置 IPC 分发
```

- 前端功能模块显式接收设备、API 和任务能力，跨功能协作通过组合入口的回调完成。没有建立相互导入状态实现的依赖。
- `serial + transportId` 继续作为设备会话身份；断线或切换设备撤销文件确认与 Owner 授权，迟到目录结果不覆盖当前设备。
- 工作台销毁会停止领域监听、设备轮询和窗口事件；重复启动或销毁不会重复注册。
- 日志暂停滚动、性能暂停采样、应用运行状态轮询保留各自语义，没有合成万能轮询器。
- `adm_call` 名称、参数及返回协议不变。后端继续执行设备会话、路径、应用版本、Owner、用户确认等校验；写任务仍使用同一互斥边界。
- 样式首轮只按连续区段搬移，固定原有顺序；保留平台覆盖、动态状态和 Teleport 菜单规则。后续合并重复选择器必须单独验证。

## 资源回收的范围

`child_process.rs` 只登记 ADM 自己启动的直接客户端，不按进程名称清理，不执行 `adb kill-server`。正常退出先拒绝新的 spawn，再终止并等待现有客户端；Logcat 停止先取消全部会话，再等待工作线程。

客户端回收和日志线程等待各有 3 秒上限，超时会记录到标准错误。设置 `ADM_PROCESS_TRACE=1` 可临时输出客户端启动和回收的 PID，不输出命令参数或设备标识。

本机实测菜单退出和关闭窗口均能回收本次 Logcat 客户端，共享 ADB server 保持运行。历史检查发现的 11 个孤立客户端没有批量终止。强制杀死宿主、系统崩溃或断电不会运行退出回调；本轮不宣称覆盖这些情况。Windows 原生进程与窗口路径仍需在对应平台验收。开发预览缩放时的一次 ResizeObserver 告警已记录在验证文档，尚未单独定位。

## 防止再次积累

- `npm run check:source` 从前端入口和单元测试跟踪本地 TypeScript / Vue 导入、字面量动态导入及命名再导出，检查缺失引用和孤立源码。它已接入 `npm run build`，现有 CI 无需增加独立步骤。
- 此检查不等于完整的未用导出或 CSS 分析，也不判断 Rust、打包资源、文档和二进制是否可删除。新增自动导入或特殊入口时，应明确调整检查规则。
- `noUnusedLocals` / `noUnusedParameters` 约束源码和测试；刻意保留的回调占位参数使用 `_` 前缀。
- 许可快照与锁文件保留。构建脚本变化后同步重生成清单，不能删除声明来消除检查错误。
- 后续业务改造、视觉调整、依赖升级和版本发布分别处理。详细命令见 [开发与构建](development.md)，本轮实测与平台限制见 [验证记录](../VALIDATION.md)。
